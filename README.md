# Synergle

A free daily puzzle in the style of NYT *Connections*, made for **Teamfight Tactics**. Each day players sort 16 champions from the current TFT set into four groups of four. Groups can be a shop cost, a trait, an ability effect, an augment, League of Legends lore or wordplay.

It's a static website: no server and no database, so you can host it for free. It's built to carry Google AdSense ads.

- **Daily puzzle.** Changes at local midnight. Includes streaks, statistics and a spoiler-free share grid.
- **Archive** of past dailies, plus **300 practice puzzles**. Each puzzle is its own page load, which means fresh ad impressions.
- **Guaranteed fair puzzles.** Every board is checked to have exactly one valid solution.
- **SEO and AdSense groundwork.** Content pages (how to play, a champion and trait guide), privacy policy, terms, sitemap, robots.txt, `ads.txt`, Open Graph image and structured data.
- **Ad slots placed with AdSense policy in mind.** Slots sit away from the game buttons, there are no ads on error pages, and space is reserved so ads don't shift the layout.
- **Current set:** Set 18, *Enchanted Wilds* (65 champions). Updating to a new set takes a few commands.

## Quick start

```bash
npm install
npm run dev        # http://localhost:8080
```

Works on Node 18+. Node 22 LTS is recommended (Node 18 is end-of-life).

During `npm run dev`, grey boxes show where ads will appear. They disappear in production builds.

## Project layout

```
site.config.json          <- site name, URL, launch date, AdSense + Analytics ids
data/
  sets/18/set.json        <- champions, traits, augments (generated by data:update)
  sets/18/curated.json    <- hand-written categories: abilities, lore, wordplay
  puzzles/daily.json      <- generated daily puzzles (append-only)
  puzzles/practice.json   <- generated practice puzzles
scripts/                  <- data pipeline, generator, validator (TypeScript, run with tsx)
shared/                   <- types + date logic shared by scripts and the browser
src/                      <- Eleventy site: pages, layouts, CSS, game code (src/assets/ts)
src/public/               <- static files copied as-is (portraits, icons, fonts, _headers)
tests/                    <- unit tests (node:test)
```

The stack is [Eleventy](https://www.11ty.dev/) for static pages, plus a small vanilla TypeScript game bundled by esbuild (about 23 KB). There's no frontend framework, so pages load fast. That helps Core Web Vitals, SEO and ad viewability.

| `npm run puzzles:generate` | Top up daily puzzles (365 days ahead) and the practice pool |
| `npm run puzzles:validate` | Check every puzzle for structure, images and a unique solution |
| `npm run brand:assets` | Regenerate favicons and the social share image |

## How puzzles are made

1. **Categories.** `scripts/lib/categories.ts` builds most categories automatically from the data: costs, traits, trait-count trivia ("Only One Trait"), augments that grant champions, attack range, and name patterns. The rest are hand-written per set in `data/sets/<n>/curated.json`. Each curated category lists its `members` plus `ambiguous` champions that arguably fit (for example, a knock-up in a stun group). Ambiguous champions are never put on a board that uses that category.
2. **Generation.** `scripts/lib/generator.ts` picks one category per difficulty (green, blue, purple, gold), avoids near-duplicate categories and recent repeats, and prefers red herrings: champions that fit two groups on the board.
3. **Fairness.** `scripts/lib/validate.ts` lists every way the 16 champions could be split into four groups that some category explains, and keeps only boards with exactly one valid split.

Puzzle files are self-contained (names, portraits, explanations), so past puzzles keep working after the champion pool changes.

### Tweaking or hand-writing categories

Edit `data/sets/18/curated.json`, run `npm run categories:report` to sanity-check it, then regenerate future puzzles:

```bash
npm run puzzles:generate -- --from 2026-10-20   # regenerate from a date (or a puzzle number)
```

Never regenerate puzzles people have already played. `--from` should always be today or later. `--reset` regenerates everything and is only safe before launch.

## When a new TFT set launches

Sets change roughly every four months. Set 19 is expected around December 2026.

```bash
npm run data:update -- --name "<New Set Name>"   # downloads the new set (data/sets/19)
cp data/sets/18/curated.json data/sets/19/curated.json   # use as a template...
#   ...then rewrite it for the new champions (abilities, lore, wordplay)
npm run categories:report                         # review the pool
npm run puzzles:generate -- --from <launch date of the new set>
npm run brand:assets                              # refresh the share image
npm run check
```

Commit and deploy. Old puzzles keep their Set 18 champions and portraits. Practice puzzles are rebuilt for the new set automatically.

A mid-set patch can change a champion's cost or traits. Run `npm run data:update`, then `npm run puzzles:generate -- --from <today>`.

## Configuration

Everything lives in `site.config.json`:

| Key | Meaning |
| --- | --- |
| `name`, `tagline`, `description` | Branding and SEO text |
| `url` | Your production URL, used for canonical links, the sitemap and share text |
| `launchDate` | The date puzzle #1 goes live. Set it to the real launch day before going live. |
| `contactEmail`, `operator` | Shown on the contact, privacy and terms pages. **Use real values before applying to AdSense.** |
| `adsense.client` | Your publisher id, `ca-pub-…`. This also generates `ads.txt` and the verification meta tag. |
| `adsense.slots.*` | Ad unit slot ids: `belowGame`, `inContent`, `railLeft`/`railRight` (desktop sidebars), `footer` |
| `analytics.gaMeasurementId` | Optional Google Analytics 4 id (`G-…`). Consent Mode defaults are set for the EEA, UK and Switzerland. |
| `puzzles.dailyDaysAhead`, `puzzles.practiceCount` | How far ahead to generate dailies, and the practice pool size |

On a hosting provider you can override these with environment variables: `SITE_URL`, `ADSENSE_CLIENT`, `ADSENSE_SLOT_BELOW_GAME`, `ADSENSE_SLOT_IN_CONTENT`, `ADSENSE_SLOT_RAIL_LEFT`, `ADSENSE_SLOT_RAIL_RIGHT`, `ADSENSE_SLOT_FOOTER`, `GA_MEASUREMENT_ID`.

## Deploying

Any static host works. Push the project to GitHub, then:

- **Cloudflare Pages** (recommended: free, fast, unlimited bandwidth). Build command `npm run build`, output directory `_site`. `.node-version` pins Node 22. `src/public/_headers` sets cache rules.
- **Netlify.** `netlify.toml` is already configured.
- **Vercel.** Framework preset "Other", build `npm run build`, output `_site`.

Connect your own domain. AdSense needs a domain you own, not a `*.pages.dev` or `*.netlify.app` subdomain.

## Making money with Google AdSense

1. **Launch first.** Deploy on your own domain and set `url`, `launchDate`, `contactEmail` and `operator`. Let the site run for a bit. AdSense reviews the site's content, and it already has an about page, how-to-play, a privacy policy, terms, a contact page and the champion and trait guides.
2. **Apply** at [adsense.google.com](https://adsense.google.com/) and add your site. Put your `ca-pub-…` id in `adsense.client` and deploy. That adds the AdSense script, the `google-adsense-account` verification meta tag and a correct `/ads.txt`.
3. **Set up consent before serving ads in Europe.** In AdSense, go to *Privacy & messaging* and create a **European regulations (GDPR)** message, which uses Google's certified CMP. Optionally add the **US state regulations** message too. Google requires a certified CMP for EEA/UK traffic. The footer's "Privacy settings" link reopens the consent message.
4. **After approval,** create five *display ad units* (responsive). Paste their slot ids into `adsense.slots` and deploy.
5. **Auto ads (optional).** Anchor and vignette formats are fine. Avoid in-page auto ads next to the board, because ads too close to game controls can count as encouraging accidental clicks, which breaks AdSense policy. The manual slots are deliberately placed away from the buttons.
6. **Don't** click your own ads or ask anyone else to. That gets accounts banned.

Revenue depends on traffic. A daily puzzle brings people back every day, and the share grid and practice/archive pages give extra page views. Good places to share it are r/CompetitiveTFT and r/TeamfightTactics (check their self-promotion rules), TFT Discord servers, and streamers.

## ⚠️ Legal notes (please read)

I'm not a lawyer. These are risks to understand before you rely on this for income:

- **Riot Games IP.** Riot's ["Legal Jibber Jabber"](https://www.riotgames.com/en/legal) policy allows fan projects to earn money through "appropriate advertisements". The same policy says *"We prohibit the use of our IP in games and apps"* without a license, and Riot's [developer policies](https://developer.riotgames.com/policies/general) say not to create games using Riot IP. Fan minigames like LoLdle exist and seem to be tolerated, but Riot could ask you to take the site down. The safest route is to email Riot or register the project in the Riot Developer Portal before investing heavily.
- **Names and domains.** Riot's policy forbids domains and social accounts that use Riot trademarks or champion names. Pick a domain like `synergle.com`, **not** `tftconnections.com` or anything with "TFT", "Teamfight", "League", "Riot" or a champion name. The required Riot disclaimer is already in the footer, and no Riot logos are used.
- **"Connections" is NYT's product name.** The site never calls itself "Connections" and uses its own design and colors. Keep it that way. Using the phrase as a description ("a connections-style puzzle") is much safer than using it as a name.
- Update `operator` and `contactEmail`, and review the privacy policy (`src/privacy.md`) for your situation. It covers local storage, AdSense cookies, consent and analytics.
